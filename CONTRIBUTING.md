# Contributing

Thanks for your interest in Amiscara Agents. Issues and pull requests are
welcome; for anything larger than a fix, please open an issue first so the
approach can be agreed on before you spend time on it.

## Ground rules

- The apps talk to an **unmodified herdr server** through its socket API.
  Features that need changes to herdr belong to the
  [herdr project](https://herdr.dev); the apps can only use what the API
  offers.
- **Never test input against a herdr session with real work.** Methods that
  write (`agent.prompt`, `pane.send_keys`, `pane.send_text`, creating
  workspaces or tabs) go only to a separate test server:

  ```sh
  herdr --session herdr-remote-test server &
  # socket: ~/.config/herdr/sessions/herdr-remote-test/herdr.sock
  herdr session stop herdr-remote-test
  ```

  Against a productive server, use read-only methods only (`ping`,
  `*.list`, `*.get`, `pane.read`, `session.snapshot`, `events.subscribe`).
- Session logic lives in `crates/herdr-session`. `herdr-ffi` (Swift and
  Kotlin bindings) and the desktop crate are thin layers over it; a change
  in behavior belongs in the shared crate so every app gets it.

## Setup

See [README.md](README.md#building-from-source) for the prerequisites per
platform. In short:

```sh
./setup.sh                  # toolchain check, build and tests; on macOS also
                            # the Swift bindings and the Xcode project
```

The Xcode project is generated by [xcodegen](https://github.com/yonaskolb/XcodeGen)
from `apps/AmiscaraAgents/project.yml`; `.xcodeproj` and `Generated/` are not
checked in. Change `project.yml`, never the generated project, and run
`xcodegen generate` in `apps/AmiscaraAgents` afterwards.

## Checks

Run before pushing:

```sh
scripts/check.sh            # cargo fmt --check, clippy -D warnings, tests, npm run check
scripts/check.sh --apple    # also builds the Mac and iOS schemes
scripts/check.sh --android  # also builds the Android app with lint
```

CI runs the full chain (Linux, macOS, Windows, iOS and tvOS, Android, the
desktop app on all systems) for every pull request.

Individual steps:

- Rust: `cargo fmt --all`, `cargo clippy --workspace --all-targets -- -D warnings`,
  `cargo test --workspace`. On Linux without WebKitGTK add
  `--exclude amiscara-desktop`.
- Desktop front end: in `apps/desktop`, `npm run check` (svelte-check,
  TypeScript); `npm run mock` shows the window with sample data in a
  browser.
- Swift bindings without UI: `scripts/ffi-smoke.sh`.

## Conventions

- **Language:** code, comments, commit messages, pull requests and issues in
  English. The user interface is German for now; UI texts use no em dash.
- **Commits:** small and focused, [Conventional Commits](https://www.conventionalcommits.org/)
  (`feat:`, `fix:`, `docs:`, `chore:`, `ci:`, `refactor:`, `test:`), with a
  scope where it helps (`feat(android): ...`). Reference the issue in the
  title, e.g. `feat: arrow keys for the pane (#123)`.
- **Changelog:** user-visible changes get an entry under `[Unreleased]` in
  [CHANGELOG.md](CHANGELOG.md) ([Keep a Changelog](https://keepachangelog.com/en/1.1.0/)).
- **Style:** follow the code around you. Rust uses the workspace lints in
  `Cargo.toml` (edition 2024, `unsafe` forbidden, no `unwrap()`);
  Swift keeps platform differences in `Platform.swift` and tvOS gaps under
  `#if !os(tvOS)`; scripts that Xcode runs must work with `/bin/bash` 3.2.
- **No secrets:** keys, certificates, keystores, `.env` files and tokens
  never go into the repository. Release keys live outside it (see
  [docs/release.md](docs/release.md)).

## Translations

The apps are written with German source texts and translated to English
(#207). New UI texts need both languages.

- **Apple apps:** one String Catalog for all targets,
  `apps/AmiscaraAgents/Shared/Localizable.xcstrings`, plus
  `AmiscaraAgents/InfoPlist.xcstrings` (permission texts) and
  `AmiscaraAgents/AppShortcuts.xcstrings` (Siri phrases). SwiftUI literals
  are picked up on build; text kept in a `String` goes through
  `String(localized:)`, and user data such as names through
  `Text(verbatim:)`. To add a language, export with
  `xcodebuild -exportLocalizations -project apps/AmiscaraAgents/AmiscaraAgents.xcodeproj -localizationPath <dir> -exportLanguage <code>`,
  translate the `.xcloc` (Xcode or any XLIFF editor) and import it with
  `xcodebuild -importLocalizations -localizationPath <dir>/<code>.xcloc`.
  Check the result by launching the app with
  `-AppleLanguages "(<code>)"`, for example on the screenshot demo
  ([docs/screenshots.md](docs/screenshots.md)).

## Pull requests

1. Fork, branch from `main`, keep the branch focused on one change.
2. Run the checks above and test in the app on the platforms you touched.
3. Open the pull request with what and why, and link the issue
   (`Closes #123`).
4. Pull requests are squash-merged once CI passes and the change is reviewed.
