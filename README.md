# herdr-remote-core

A graphical remote for [herdr](https://herdr.dev), the agent multiplexer for the
terminal, on iPad, iPhone, Mac and Windows. This repository holds the Rust core
that talks to an unmodified herdr server, locally over its Unix socket or
remotely over SSH. Herdr Remote is a working title and an unofficial project,
not affiliated with herdr.

## How it connects

herdr exposes a newline-delimited JSON API on `~/.config/herdr/herdr.sock`.
Remotely, the core opens one SSH session and a `direct-streamlocal@openssh.com`
channel per request straight to that socket. Nothing is installed on the server.

A dedicated key can be locked down in `~/.ssh/authorized_keys` so that it can
open channels but never run a shell or command:

```
restrict,port-forwarding,command="/usr/bin/false" ssh-ed25519 AAAA... herdr-remote
```

`restrict,port-forwarding` alone still lets the key run commands.

`port-forwarding` also allows TCP forwarding through the server, so a stolen
device key could reach other machines from there. `permitopen` does not help:
sshd applies it to the streamlocal channel too and then refuses `herdr.sock`
(OpenSSH 10.3). If no other login needs it, `AllowTcpForwarding no` in
`sshd_config` closes TCP forwarding for everyone. Otherwise use one key per
device and remove a lost device's line right away.

## Layout

- `crates/herdr-proto`: request, response and event types, protocol version check
- `crates/herdr-transport`: local socket and SSH streamlocal transport, requests and event subscriptions
- `crates/herdr-core`: session state from snapshot and events, agent board, sync driver with reconnect, pane content as styled lines
- `crates/herdr-ffi`: UniFFI bindings for the apps (`scripts/build-ffi.sh` builds the XCFramework and Swift code)
- `crates/uniffi-bindgen`: the binding generator, kept out of the app library
- `crates/herdr-spike`: read-only command line probe (`ping`, `list`, `read`, `watch`, `board`, `check`, `view`, `bench`)
- `docs`: research and design notes

- `apps/HerdrRemote`: SwiftUI app for Mac (macOS 27), iPad and iPhone (iOS 27), project generated by xcodegen

Planned: Tauri for Windows.

## Setup

Requires a stable Rust toolchain (edition 2024).

```sh
./setup.sh          # checks the toolchain, builds and tests
cargo run -p herdr-spike -- ping
cargo run -p herdr-spike -- --ssh user@host --identity ~/.ssh/key bench
```

The spike only calls read-only methods. Pass `--accept-new-host-key` once to
record an unknown host key.

## Apple apps

```sh
./setup.sh    # also builds herdr-ffi and runs xcodegen on macOS
xcodebuild -project apps/HerdrRemote/HerdrRemote.xcodeproj -scheme HerdrRemote \
    -derivedDataPath target/xcode build
open target/xcode/Build/Products/Debug/HerdrRemote.app
```

iPad and iPhone (scheme `HerdrRemote-iOS`, same sources). Build, install and
launch on a connected device with developer mode on:

```sh
scripts/install-ios.sh                # the only connected iPhone or iPad
scripts/install-ios.sh "iPad (2)"     # by name or UDID when several are connected
scripts/install-ios.sh --release      # Release build; --no-launch installs only
```

On iOS there is no local socket; hosts are SSH only. The app reconnects as
soon as it returns to the foreground. `scripts/build-ffi.sh` builds the slice
the current Xcode platform needs and keeps the others in the framework.

`scripts/ffi-smoke.sh` exercises the Swift bindings without the UI against
the local server; with `HERDR_SMOKE_SSH=user@host HERDR_SMOKE_KEY=<key>` it
also runs the SSH and host key flow.

The app shows hosts, workspaces, the agent board and the live pane screen.
Under the pane it sends prompts to agents, text to shells and keys such as
Enter, Esc or 1/2/3 to answer an agent waiting for approval. Each host has a
switch to keep it read-only.

### Organizing spaces: `Bereich/Name`

herdr has no folders above spaces. The app groups spaces by name instead:
everything before the first `/` is the group, the rest is the space's name.

```
Privat/Bürgertreff      → group "Privat":  Bürgertreff
Privat/Dorfkino         →                  Dorfkino
Arbeit/energieausweis   → group "Arbeit":  energieausweis
```

Each group is a foldable row with its number of spaces and waiting agents;
folding is remembered per device. Groups appear where their first space is
in herdr's order, spaces without `/` stay where they are. Spaces around the
`/` are ignored (`Privat / Dorfkino`), a name with an empty part (`/Dorfkino`,
`Privat/`) is not grouped. Linked worktrees stay under their repository, even
when their branch looks like `feature/x`. The name lives on the server, so
iPad, iPhone and Mac show the same groups without any sync; herdr itself
simply shows the full name. Name a space this way when creating it or via
"Umbenennen …".

Images: the paperclip in the composer uploads pictures to
`~/.herdr-remote/uploads/` on the host and appends their paths to the prompt.
For SSH hosts this needs the switch "Bilder hochladen (SFTP)" and the key line
with `command="/usr/libexec/sftp-server"` instead of `/usr/bin/false`. That key
can then read and write every file of the user, including
`~/.ssh/authorized_keys`, so it is effectively full access to that account.

Test input only against a separate session, never the one with real work:

```sh
herdr --session herdr-remote-test server &
HERDR_SMOKE_WRITE_SOCKET=~/.config/herdr/sessions/herdr-remote-test/herdr.sock \
    scripts/ffi-smoke.sh
herdr session stop herdr-remote-test
```

```sh
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
```
